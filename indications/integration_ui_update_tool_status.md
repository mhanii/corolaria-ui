# UI Integration Guide: Tool Status Improvements (February 2026)

This guide details the recent updates to the Server-Sent Events (SSE) streaming and tool summary persistence. The primary goal is to improve user visibility into **what** the AI is searching for, and to provide much cleaner handling of **non-critical errors** (soft errors) generated by the LLM.

---

## 1. Streaming Events (`tool_start` and `tool_end`)

Previously, when a tool executed, the backend emitted the technical name of the tool. Now, if the tool has a search parameter ([query](file:///home/hani/corolaria/src/ai/agents/tools.py#113-160) or `document_text`), the SSE event is automatically formatted in natural language and includes the search terms.

### Expected format in the SSE stream ([chat_stream](file:///home/hani/corolaria/src/domain/services/langgraph_chat_service.py#650-935)):
```json
// Event when STARTING the search:
{
  "type": "status",
  "phase": "tool_start",
  "message": "Buscando 'ley de costas'...",
  "source": "tool_executor",
  "tool": "fast_research_tool"
}

// Event when FINISHING the search:
{
  "type": "status",
  "phase": "tool_end",
  "message": "Búsqueda de 'ley de costas' completada",
  "source": "tool_executor",
  "tool": "fast_research_tool"
}
```

### ✅ Action required by the Frontend:
- The [message](file:///home/hani/corolaria/src/infrastructure/database/mariadb_conversation_repository.py#149-227) property is already formatted and ready to display.  
- If you use the `label` directly from the stream, you can rely on it containing descriptive information instead of just "Ejecutando internet_search...". You do not have to parse the search arguments manually in the UI.

## 2. Tool Error Events (`tool_error`)

There are occasions when tools "fail gracefully" (Soft Errors). For example, when [create_legal_document](file:///home/hani/corolaria/src/ai/agents/tools.py#691-807) is called without having gathered legislation first. Previously, these failures produced raw JSON that was hard for the user to read, or were falsely emitted as `tool_end` messages.

Now, they are correctly identified under the same generic status structure (`type="status"`), using a new `phase="tool_error"`. In addition, the text from the backend has been safely truncated to less than 50 characters (e.g., *"No Context"*, *"Missing parameter"*).

### Expected format in the SSE stream:
```json
{
  "type": "status",
  "phase": "tool_error",
  "message": "Error en create_legal_document: No hay contexto di...",
  "source": "tool_executor",
  "tool": "create_legal_document",
  "error_code": "soft_error",
  "retry_suggested": false
}
```

### ✅ Action required by the Frontend:
- **Error UI Rendering:** These events are sent in the same way as normal statuses. We suggest that you evaluate the `tool_error` phase to, for example, apply a faint red color to this inline status, showing the user that this specific underlying action organically failed, even while the overall agent continues responding.
- The [message](file:///home/hani/corolaria/src/infrastructure/database/mariadb_conversation_repository.py#149-227) property is ready for consumption and has been safely truncated to fit nicely in a standard chat modal/toast.

## 3. Unified Summary Persistence ([tool_summary](file:///home/hani/corolaria/src/domain/services/langgraph_chat_service.py#478-619))

When a conversation thread is retrieved from the API with persisted messages (`/api/v1/beta/conversations/{id}/messages`), tool executions are stored under `role="tool"`. Now, the database includes the query ([query](file:///home/hani/corolaria/src/ai/agents/tools.py#113-160)) in the `label` property of the [tool_summary](file:///home/hani/corolaria/src/domain/services/langgraph_chat_service.py#478-619).

It will also explicitly register the prefix "Error:" in the summary label if the request for that tool reported a Soft Error.

### Model returned from the API:
```json
{
  "role": "tool",
  "content": "...[full text for the llm]...",
  "tool_summary": {
    "tool_name": "internet_search",
    "label": "Búsqueda en internet: 'elecciones recientes' (12 resultados)" 
  }
}

// Or in the event of a persisted Soft Error:
{
  "role": "tool",
  "tool_summary": {
    "tool_name": "create_legal_document",
    "label": "Error: NO_CONTEXT" 
  }
}
```

### ✅ Action required by the Frontend:
- Continue rendering the `tool_summary.label` property when loading previous histories just as you usually do. The backend has already processed the error logic, temporal unification, and argument reading, so this UI component will adapt in real time once its persistence is consumed transparently.
